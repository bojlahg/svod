# Свод (svod) — техническое задание

«Свод» — локальная база знаний на основе mozg. Пользователь создаёт базы, собирает готовые Markdown-заметки и выдаёт агентам доступ через MCP. Базу можно перенести на другой сервер вместе с заметками и готовыми векторами.

Основной сценарий — администратор разворачивает «Свод» в Docker, создаёт базу `Unity`, загружает папку с рецептами, обновляет индекс и выдаёт агенту токен для работы с `Unity`, `Git` и `CSharp`.

## Интерфейс и навигация

- Компактный тёмный интерфейс с почти чёрным фоном, читаемым текстом и плотными списками. Слева дерево баз, папок и заметок. Справа содержимое выбранной заметки.
- Дерево раскрывается по уровням. Например, `Unity → UI → Moon.Controls → Создание кнопки`. Пользователь может создавать и переименовывать базы и папки, а также переносить заметки между папками. При переносе ID заметки сохраняется.
- В базе доступны поиск, добавление заметки, импорт, экспорт, обновление эмбеддингов и предложения агента. В интерфейсе видны количество предложений на проверке и состояние индексации.
- Результат поиска показывает название заметки и путь к ней. При открытии результата дерево раскрывается до нужной папки и выделяет заметку.
- В режиме чтения Markdown отображается с заголовками, списками, таблицами, ссылками, встроенным кодом и подсветкой блоков кода. Редактирование открывается отдельной кнопкой.
- Рядом с редактором есть сворачиваемая подсказка «Синтаксис Markdown» с короткими примерами для заголовка, списка, ссылки, таблицы и кода. «Предпросмотр» использует то же оформление, что и режим чтения.

## Заметки и источники

- Пользователь с правом редактирования может создать, изменить, перенести и удалить заметку. Заметку можно написать в редакторе или загрузить как готовый `.md`.
- «Свод» принимает готовый Markdown из редактора, MCP, отдельных файлов, папки или ZIP. Один `.md` становится одной заметкой. При импорте сохраняются язык, текст, блоки кода и относительная структура папок. Исходный Markdown доступен для чтения, редактирования и выгрузки.
- Убрать загрузку и обработку веб-страниц, PDF и других форматов, а также конвейер извлечения, пересказа и перевода через LLM. Импорт, чтение и поиск работают без ключа платной LLM.
- Эмбеддинги служат для поиска по уже готовому тексту. Длинную заметку можно индексировать по разделам, сохраняя её как одну запись. По совпадению агент получает релевантный фрагмент и может открыть заметку целиком.

## Администратор, пользователи и MCP

- Администратор задаётся через `MOZG_ADMIN_EMAIL` и `MOZG_ADMIN_PASSWORD` в `.env`. При первом запуске приложение создаёт аккаунт. Смена `MOZG_ADMIN_PASSWORD` и перезапуск обновляют пароль администратора.
- В разделе «Пользователи» администратор добавляет пользователей, редактирует их данные, управляет их паролями и назначает доступ к базам. Администратор также может редактировать базы и заметки и принимать предложения агентов.
- Один MCP-токен открывает доступ к нескольким выбранным базам. Для каждой базы отдельно задаётся право чтения или чтения и отправки предложений. Например, один токен может предлагать заметки в `Unity` и читать `Git` и `CSharp`.
- MCP проверяет права токена при перечислении баз, поиске, чтении заметки по ID и отправке предложения. Базы вне выданного доступа скрыты от токена. Токен можно отозвать.
- Агент отправляет готовую Markdown-заметку. Предложение попадает в очередь проверки с указанием токена, которым его отправили. Поиск видит заметку после принятия. Пользователь с правом проверки может отредактировать предложение и принять его либо отклонить. Принятая заметка индексируется по настройкам базы.

## Память проекта и общие базы

- «Свод» поддерживает общие базы по темам (`Unity`, `CSharp`, `Git`) и отдельные базы проектов. База проекта связана со стабильным ID проекта, который передаёт агент или его конфигурация. Проекты с одинаковыми отображаемыми названиями могут иметь разные ID.
- Для работы над проектом агент сначала ищет в его базе, затем при необходимости дополняет контекст из доступных общих баз. Источник каждого результата виден агенту.
- Настройки сборки, причины принятых решений, внутренние соглашения и обходы проблем конкретного проекта агент предлагает в базу этого проекта. Рецепт, который полезен и в других проектах, агент может предложить в общую базу по теме. Например, правило выбора формата импорта текстуры можно предложить в `Unity`, а настройки импорта для конкретного проекта — в его базу. Если заметка объединяет оба вида знаний, агент может предложить их отдельно. При сомнении выбирает проектную базу.
- Если базы проекта ещё нет, агент может создать приватную базу по ID проекта. Для этого у токена должно быть отдельное право создания проектных баз. Повторный запрос с тем же ID возвращает существующую базу, если токен уже имеет к ней доступ. Создавший базу токен получает право читать её и предлагать заметки, а доступ для остальных выдаёт администратор.
- Предложения в обеих базах проходят ручную проверку. В очереди видно, в какую базу предложена заметка. Проверяющий может сменить базу перед принятием, если у него есть права на обе. Если токену не хватает прав на целевую базу, агент сообщает об этом и сохраняет предложенный Markdown в ответе пользователю.

## Индексация и скорость поиска

- Для каждой базы доступны кнопка «Обновить эмбеддинги» и переключатель автоиндексации. Статус показывает заметки, ожидающие индексации, текущий прогресс и ошибки. При обычном обновлении эмбеддинги считаются только для новых и изменившихся разделов.
- Поиск по точному ID рецепта работает без расчёта эмбеддинга запроса. Для повторных запросов можно использовать кэш векторов с учётом модели и её настроек. Индексация идёт небольшими пакетами, между которыми поисковые запросы получают приоритет.
- По умолчанию модель работает на CPU. Для замеров сравнить BGE-M3 с 2 и 4 потоками на NAS. Отдельно проверить ту же модель на RTX 5060 Ti через `EMBED_QUERY_URL`. При совпадении модели и настроек расчёта готовые векторы используются повторно.
- Исходный замер на NAS с Celeron J4125 дал медиану **0,69 с** на одиночный `brain_search`, из которых **0,52 с** ушло на эмбеддинг запроса. Три одновременных вызова заняли **1,52–1,60 с** каждый. При приёмке повторить одиночный и параллельный замеры, измерить поиск во время индексации и проверить попадание нужных рецептов в выдачу на одинаковых русских и английских запросах.

## Экспорт и импорт отдельной базы

В меню базы доступны «Экспорт» и «Импорт». У экспорта два формата.

| Формат | Что содержит | Как используется |
| --- | --- | --- |
| Полный ZIP «Свода» | Структура папок, заметки с ID и статусами, предложения на проверку, существующие вложения и готовые векторы с данными о модели | Перенос или восстановление базы в другом экземпляре «Свода». При совпадении модели и настроек эмбеддингов используются готовые векторы. При несовпадении заметки помечаются для переиндексации. |
| ZIP с Markdown | По одному `.md` на заметку в папках, соответствующих дереву базы. Текст и блоки кода сохраняются как есть. | Чтение в Obsidian, хранение в Git или повторный импорт Markdown. |

- Импорт поддерживает полный ZIP «Свода», ZIP с Markdown, папку и отдельные `.md`. Данные можно загрузить в новую или существующую базу.
- Перед импортом в существующую базу показать, какие заметки добавятся и где обнаружены совпадения. Для совпадений доступны «Обновить» и «Пропустить». Повторный импорт не создаёт дублей.

## Что убираем из mozg

- Тарифы, баланс, оплату, пополнение, историю операций, продажи и публичный каталог. «Библиотека» с сохранением чужих баз также удаляется. Свои базы открываются из дерева.
- `chatmozg`, `Your page` и достижения, включая пункты меню, связанные страницы, значки, уведомления и начисление достижений.
- Весь модуль экзаменов, включая экраны, оценки, генерацию вопросов и фоновые задания. При обновлении с mozg отменяются незавершённые задания экзаменов. Ручная проверка предложений агента остаётся в интерфейсе. Сценарии Mode C остаются внешней приёмкой Unipedia.

## Установка и обновление

- Основной способ установки — стандартный Docker Compose. Один комплект подходит для Linux-хоста, Docker Desktop на Windows или macOS и Synology Container Manager.
- В ZIP релиза входят `compose.yaml`, `.env.example` и короткая инструкция. Пользователь создаёт `.env` по примеру, задаёт почту и пароль администратора и запускает `docker compose up -d` или открывает тот же `compose.yaml` в Container Manager. Compose скачивает готовые образы «Свода», PostgreSQL и сервиса эмбеддингов.
- Приложение дожидается PostgreSQL, применяет миграции схемы, настраивает администратора и начинает принимать запросы. Ошибка миграции видна в логе и статусе контейнера. Отдельный контейнер `migrate` и ручная команда создания администратора убираются.
- Пока модель впервые загружается, интерфейс показывает её статус. Пользователь уже может просматривать и редактировать Markdown. Заметки, векторы и веса модели хранятся в постоянных томах Docker.
- Обновление выполняется выбором нового тега образа и перезапуском проекта с теми же томами. Отдельно проверить обновление текущей базы mozg на «Свод» с сохранением имеющихся заметок и совместимых векторов.

## Приёмка

1. Развернуть «Свод» с нуля на обычном Docker-хосте и на Synology без Git, сборки исходников и ручных команд внутри контейнеров. Войти администратором из `.env`, проверить смену его пароля через перезапуск, добавить пользователя и назначить ему права на базу.
2. Загрузить папку с Markdown, сверить дерево и исходный текст. Проверить просмотр таблиц и блоков кода, подсказку и предпросмотр в редакторе. Отредактировать заметку, обновить индекс и найти новую версию. Перенести заметку между папками и открыть её по прежнему ID.
3. Выдать одному токену доступ к `Unity`, `Git` и `CSharp` с разными правами. Проверить поиск и чтение в разрешённых базах, отказ при обращении к закрытой базе по известному ID и отказ после отзыва токена. Предложить заметку в `Unity`, проверить её отсутствие в поиске до принятия, принять и найти после индексации.
4. Восстановить полный ZIP на втором экземпляре с той же моделью и подтвердить поиск по готовым векторам. Выгрузить ZIP с Markdown и повторно импортировать его с сохранением текста и папок. Проверить «Обновить» и «Пропустить» при совпадениях.
5. Замерить скорость поиска по точному ID и обычного поиска. Сравнить одиночный запрос, три одновременных запроса и запрос во время индексации. На одном наборе запросов проверить качество выдачи для каждого варианта настройки эмбеддингов.
6. Создать проектную базу через MCP по новому ID и повторить запрос, чтобы проверить, что база одна. Предложить настройку сборки в проектную базу и общий рецепт в `Unity`. Проверить, что обе заметки доступны поиску после принятия, а токен без доступа к проекту не может открыть его базу. Повторить создание под токеном без соответствующего права и проверить отказ.
